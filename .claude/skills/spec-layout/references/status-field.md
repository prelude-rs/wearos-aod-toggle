## Status field

Part of the `spec-layout` skill — read when the approval digest or the design transcription's folder move matters.

**The marker is verifiable, not merely attributable.** Alongside `approved-by` (who + when), the transcription stamps a sibling **`approved-content`** marker carrying a digest of the approved content — so the record says **what** was approved, and recomputing the digest separates *approved-and-intact* from *approved-and-changed*. Two consequences follow: `! sdd-approve` on an already-`Approved` artifact **re-approves** when the content has changed since (and still refuses when it has not), and the agent never writes that marker — a digest the agent wrote would only manufacture false assurance. **The digest computation — what enters it — lives in the code gate hook (`require-approved-spec.sh`, function `content_digest`), while reading the recorded marker lives in the common hook library (`hooks-lib.sh`, `hk_marker_value`), used by the gate and by the approval script; the rule is not restated here.** Editing `spec.md`/`design.md` never triggers the code gate. The next code edit does, and blocks if the digest diverges — re-transcribe. **An `approved-content` marker the repository history shows and the file no longer carries counts as divergence (a *removal*), never as hand approval** — the code gate reads that history, and the agent never removes the marker.

**The design transcription moves the folder.** `sdd-approve spec|design <id>` looks for the change in `specs/proposed/` first, then `specs/active/` (legacy and fast lane). For a change in `proposed/`, `design` refuses if `specs/active/<id>/` already exists, runs its checks (the coverage check with `--transcricao`, which requires `## Decomposição`, and the report check), transcribes, and then moves the folder to `specs/active/` (`git mv` when tracked); a design already approved there with an intact digest is only moved. Exit codes: 2 refused before anything was written, 4 a check failed (nothing written, nothing moved), 5 transcribed (or already approved) but not moved (the message says what was done and, when the destination is free, the manual move command). The digest does not depend on the path, so moving never invalidates an approval. **Residual:** the code gate reads the marker history by path, so a single commit that moves the folder *and* deletes the marker by hand is not read as a removal — the agent does not delete the marker (instruction, not enforcement), so only a human would.
