## Protocol tokens

Part of the `spec-layout` skill — read when writing or reading a protocol token (`Status:`, `Verdict:`, `NO-TASK:`, `SOT-NO-DELTA:` …).

- **Protocol tokens stay English/neutral regardless of prose language.** The `Status:` field and its values (`Draft`/`In Review`/`Approved`, `Pending`/`Complete` — the require-approved-spec hook greps for `Approved`), the **epic map row's closing destination** (`done` / `pending` / `cut` / `deferred` — the first word of the row's last cell, read by `tests/check-epic-closing.sh`; free prose may follow the token), the **`Verdict:` field** and its values (`PASS`/`FAIL` in `consistency-report.md`, `COMPLETE`/`INCOMPLETE` in `evidence.md`), requirement/NFR IDs (`R1`, `N1`), the **`NO-TASK:` token** in a requirement's acceptance cell (read by `.claude/hooks/check-tasks.sh` — see below), the **`SOT-NO-DELTA:` token** in a spec's/`change.md`'s "Seções do SoT afetadas" declaration (read by `sot_decl_of` in `.claude/hooks/hooks-lib.sh`, which both `verify-archived-gates.sh` and `.claude/hooks/check-tasks.sh` call), the **Gate 1 reopening motive tokens** (`CONTRADICTION`/`UNVERIFIABLE`/`OVERSPECIFIED`, the values a reopening item's `motivo:` field takes in `consistency-report.md`, read by `tests/check-spec-layout.sh` — the consistency-gate skill owns the item's exact form), the **two closing-row tokens of `tasks.md`** (`validation-gate` and `sign-off`, matched by the same check in the last two ledger rows — translating either breaks the aferição, which is precisely why they are identifiers and not prose), the **`AVISO`/`AVISOS: <n>` tokens** (three emitters in `.claude/hooks/check-tasks.sh`, one printer and one counter: the onde-dentro alarm — `AVISO <spec>:<id> [classe] …` per match, read by the consistency-gate's check 6b as its starting list —, the sizing alarm — `AVISO <change> [dimensionamento] <n> tasks — justificado`, read by check 6c and ignored by 6b — and the SoT-declaration warnings — `AVISO <pasta> [sot] …` for a heading of the spec's "Seções do SoT afetadas" that is absent from or repeated in the SoT at `HEAD`, or for a repository with no SoT at `HEAD` (rule 5(b)), ignored by 6b; `AVISOS: <n>` is the run's total over the three; the hook's user-facing-message carve-out does not cover them, since the gate greps them mechanically), the **`**Justificativa de dimensionamento:**` label** (the sizing justification line of `design.md`'s `## Decomposição`, required above 16 blocks — rule 2 — and read by `.claude/hooks/check-tasks.sh`), the **plan's machine-read forms** — `## Decomposição` (the literal heading of `design.md`'s last section), `### Task N` (one block per task), `**Refs:**` (the block's ids line), `**Visual:** sim` (the block's VISUAL mark), the ledger header `| # | Task | Visual | Status | Commit | Notas |` and `check-tasks.sh`'s `--ledger` flag (the Superpowers brief extractor reads `### Task N`; `.claude/hooks/check-tasks.sh` reads the rest and accepts `--ledger`), the **`Reaberturas do Gate 1 propostas: <n>` counter line** (the `### Reabertura do Gate 1` subsection of a `consistency-report.md`, read by `tests/check-spec-layout.sh`), the **report's round and finding forms** (their rules are owned by the `consistency-gate` skill, section "Output" — not restated here): the whole-line heading **`## Rodadas`** (one count row per gate run; read by `.claude/hooks/check-report.sh` as the marker of the report's current form), the **`Base` column** of that table (its 6th header cell, exactly `Base`; `check-report.sh` switches the round and stop rules on by it), the stop decision line under that table, by the prefix **`- Parada após a rodada `** (`- Parada após a rodada <N>: <quem>, <AAAA-MM-DD> — <opção> — teto +<K>`, read by `check-report.sh`; its form and the ceiling count are owned by the `consistency-gate` skill, section "Output"), **`BLOCKING`/`WARNING` as the finding class** (the `Classe` cell of a finding row under a `## Check …` heading; `check-report.sh` counts the `BLOCKING` rows against the `Verdict:`), the **`**Justificativa de tamanho:**` label** (required above 100 lines outside HTML comments, read by `check-report.sh`) and that hook's **`AVISO <dir> [tamanho] <n> linhas — justificado`** line (printed when a long report is justified, and counted in its own `AVISOS: <n>`), the **closing-debt warnings** — `AVISO dívida de fechamento: …` lines plus their own `AVISOS: <n>` counter, printed by `.claude/hooks/check-closing-debt.sh` (exactly one counter line on every run over a root; another script that emits the token, never a failure — only a usage error exits 2, without the counter), the **`specs/proposed/` path** (where a change lives until Gate 1.5 — read by the approval launcher, `check-tasks.sh` and `check-report.sh`, and recognized only as a folder directly under `specs/proposed/`), the **epic legacy line** — `` - `<NNN-name>.md` e `<NNN-name>.md` — <motivo> `` in `specs/epics/LEGADO-NUMERACAO.md` (read by `.claude/hooks/check-epic-numbering.sh`), the **release changelog's machine-read forms** (the rule lives in `spec-layout` → "Changelog de release" — not restated here): the section heading **`## [Unreleased]`** and **`## [x.y.z]`**, the item reference **`(seq N)`** / **`(seq N, #PR)`**, and the labelled lines **`**Changes de release (sem item):**`** and **`**Ledger anterior a este arquivo:** seq ≤ N`** (read by `.claude/hooks/check-release-changelog.sh`), and code identifiers (symbols, columns, flags, paths) are anchors the hooks, gates, and commits reference across translation — never translate them.
  **`NO-TASK:` is machine-read ANCHORED AT THE START of the requirement's acceptance cell** (the cell whose header names `Acceptance`, found by name — never by ordinal, because 3 of 43 archived specs have a 3-column requirement table where the "4th cell" is out of range). It exempts that `R*` from the coverage aferição, and **an empty motive fails**: `NO-TASK:` alone never passes by omission. The anchoring is not decoration — measured, a "contains" read already false-fired on a requirement whose own subject was *registering* this token, exempting it by a rule nobody invoked. Same discipline as `^Status:` and `^Verdict:`, one level down: cell start instead of line start. **The `Verdict:` field is machine-read as the FIRST `^Verdict:` line in the file** (the require-approved-spec hook and `verify-archived-gates.sh` use `grep -m1 '^Verdict:'`, matching the token with `-w` so `COMPLETE` ≠ `INCOMPLETE`): keep it as a header field at the top, above any prose or fenced/quoted examples, so a quoted token lower in the report can't be mistaken for the verdict.
  **`SOT-NO-DELTA:` is machine-read ANCHORED AT THE START of a line** (`^SOT-NO-DELTA:`) inside the "Seções do SoT afetadas" declaration section, **read after HTML comments are stripped from that line** (the template emits the token inside an instruction comment, and an unstripped read would false-fire on the template text itself — same lesson as `NO-TASK:`), English, never translated; the motive after the colon is required and **a non-empty motive is mandatory** — `SOT-NO-DELTA:` alone never passes by omission. **Provenance forms** — the vocabulary `sot-history-lint.sh` dispenses so a legitimate pointer to an archived change is never mistaken for loose narrative — are exactly three, defined here as the single portable source: **an `` archive/<id> `` path, in backticks or bare (a change-id immediately preceded by `` archive/ `` is never an occurrence); `` ADR NNNN ``; a parenthesized group containing a change-id in backticks, an `` archive/ `` path, or `` ADR NNNN `` (every change-id inside such a group is dispensed).** Any of the three may span more than one line within the same paragraph — the lint reads paragraph by paragraph, not line by line, so a form broken across a line wrap still counts.
